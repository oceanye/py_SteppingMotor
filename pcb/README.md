# ESP32-S3 六路 DM422 + 三路 DRV8871 模块载板

这是一块面向当前 `esp32s3_gear` 固件的 **180 × 210 mm 双层模块载板**。设计目标是把现有成品模块和外部驱动器可靠地接起来，而不是把 ESP32、DRV8871、DM422、TCA9548A、PCF8575 或 RS485 模块拆成芯片级电路。

板上支持：

- 1 块 ESP32-S3-DevKitC-1（2×22P 排母插接）；
- 6 套外置 DM422 的 PUL/DIR 信号端子；
- 2 块闭环 GEAR 用 DRV8871 成品模块及 2 路编码器端子；
- 第 3 块独立 DRV8871 成品模块，用于轨道 D 前进/后退；
- 1 块可选/DNP 的 TCA9548A 成品模块和 6 组 `3V3/GND/SDAx/SCLx` AS5600 接口；
- 1 块可选/DNP 的 PCF8575 成品模块，P0-P5 预留 DIR0-DIR5、P6-P11 预留 ENA0-ENA5；
- 1 组 3.3 V 多功能扩展排针；GPIO42/47 可作共享 I²C SDA/SCL，也可在停用 I²C 后改作 UART/RS485；
- 1 个可选的成品 RS485 收发模块占位及 A/B/GND 端子；
- 全板公共 GND、独立 `3V3` / `5V_USB` / `VM_MOTOR` 电源域。

> **本版本的模块机械尺寸均为 MOCK。禁止按当前占位直接批量打样。拿到实物后先测量模块外形、排针中心距、孔位和引脚顺序，再修改 `generate_pcb.py` 顶部的 `MODULE_GEOMETRY`。**

## 模块接入硬约束

本板只做**完整成品模块的载板**，不把任何模块拆回芯片级电路：

| 对象 | 当前接入方式 | 后续允许的替代方式 |
|---|---|---|
| ESP32-S3 DevKit | 2×22P、2.54 mm 排母插接 | 仅在更换为带邮票孔的完整 ESP32 模组板后制作其专用封装 |
| DRV8871 ×3 | 完整驱动模块通过排针/排母插接，电机端仍使用模块自带端子 | 按真实模块邮票孔制作专用封装 |
| TCA9548A | 完整多路复用模块通过排针/排母插接 | 按真实模块邮票孔制作专用封装 |
| PCF8575 | 完整 GPIO 扩展模块通过排针/排母插接 | 按真实模块邮票孔制作专用封装 |
| RS485 | 完整收发模块通过排针/排母插接 | 按真实模块邮票孔制作专用封装 |
| AS5600 ×6 | 完整传感器模块安装在电机轴端，通过四线端子/线束回到载板 | 若机械结构允许，可把真实模块邮票孔直接焊在轴端小板，不能把传感器芯片直接放到主载板 |
| DM422/DM442 | 完整外置驱动器，通过PUL/DIR端子线束连接 | 不安装到本载板，也不拆解其功率级 |

排针方案适合当前尺寸未定、需要更换和调试的阶段。邮票孔只适用于**模块本身已经提供邮票孔边缘焊盘**的情况；必须拿到实物或正式机械图后，按边缘焊盘节距、长度、板边偏移、模块外形和底部禁布区制作专用 footprint。不存在可安全通用的“任意模块邮票孔封装”。

当前 KiCad 文件采用排针/通孔模块插座作为 MOCK 基线。后续确认某个模块使用邮票孔时，只替换该模块 footprint，保持网络名、固件引脚和其他模块不变。

`config.h` 中 GEAR 的 IN1/IN2 和 ENCA/ENCB 是为了 PID 正方向而交换后的**逻辑名**；上表和 PCB 丝印使用模块、编码器的**实体脚名**。不要把逻辑名直接当作模块脚名。GPIO48 在部分 DevKit 版本连接板载 RGB LED，因此 AUX/RS485 正式启用前必须确认实际开发板版本。

当前编码器尚未安装，六路 DM422/DM442 必须继续使用 ESP32 原生 PUL/DIR 开环链路。
TCA9548A、六块 AS5600 和 PCF8575 均为可选后装/DNP 预留，不得成为当前开环运行的
前置条件。TCA9548A 与 PCF8575 可以在同一 GPIO42/47 I²C 总线上并存；I²C 与 AUX
UART/RS485 互斥，切换用途前必须同步修改固件配置。

## 接口定义

### 六组 DM422 信号

`J_DM0_SIG` 到 `J_DM5_SIG` 均按以下顺序：

| Pin | 信号 | 接 DM422 |
|---|---|---|
| 1 | 对应 GPIO PUL | PUL+ |
| 2 | GND | PUL− |
| 3 | 对应 GPIO DIR | DIR+ |
| 4 | GND | DIR− |

DM422 的 24 V 电机电源 **不经过本载板**。六套 DM422 应使用额定电流足够、带保险的成品 24 V 分配模块或端子排独立布线；24 V 负极与本板 GND 在系统内共地。

**ENA+/ENA- 不经本载板**（`J_DMx_SIG` 只引出 PUL/DIR 4P 信号，每轴只需 PUL+ 和 DIR+ 两根信号线到 ESP32）。DM422/DM442 的 ENA 保持**悬空即默认使能**驱动；如未来要软件控制使能（如急停时失能输出），须经 PCF8575 等扩展器并加成品开集电极/ULN 缓冲模块（当前固件未实现，且 PUL 永远留在 ESP32 原生 GPIO，I²C 扩展器做不了脉冲）。

### DRV8871 成品模块

`U_DRV0`、`U_DRV1`、`U_DRVD` 当前假设模块逻辑排针为：

| Pin | 信号 |
|---|---|
| 1 | VM_MOTOR |
| 2 | GND |
| 3 | IN2 |
| 4 | IN1 |

电机线接 DRV8871 模块自带的 Motor+/Motor− 螺钉端子，不绕回载板。三个模块共用 `J_VM_IN` 的独立低压电机电源。

`J_VM_IN` 只允许接符合 N20 和轨道 D 电机额定电压的低压电源。**不要把 DM422 的 24 V 接到 `J_VM_IN`，也不要把 24 V 直接接到 N20/DRV8871。**

### 编码器

`J_ENC0`、`J_ENC1`：`3V3 / GND / A / B`。若实物编码器输出不是 3.3 V 兼容电平，须使用成品电平转换模块，不要直接接 ESP32。

### UART / I²C / RS485 扩展

`J_AUX_UART`：`5V_USB / 3V3 / GND / TX或SDA(GPIO42) / RX或SCL(GPIO47) / DE(GPIO48)`。

- Pico/RP2040 的 UART 逻辑必须是 3.3 V；
- I²C 模式下 GPIO42/47 分别作为 SDA/SCL，可同时接 TCA9548A 与 PCF8575；
- I²C 只建议承担 DIR、ENA、限位等低速信号，不用于实时生成 DM422 的 PUL；
- `5V_USB` 只来自 DevKit USB/5V 引脚，不与 `VM_MOTOR` 相连；
- 连接外部 Pico 时只选一种供电路径，避免两个 USB 电源互相回灌；
- 可选 `U_RS485` 使用成品 3.3 V RS485 模块，`/RE` 与 `DE` 共用 GPIO48；
- TTL UART、I²C 与 RS485 模块共用 GPIO42/47；I²C 模式与 UART/RS485 模式互斥；
- RS485 外部端子 `J_RS485` 为 `A / B / GND`。

### 可选六路 AS5600 诊断

启用后的诊断拓扑为 GPIO42(SDA) / GPIO47(SCL) → TCA9548A `0x70` → 通道 0–5 →
各一路 AS5600 `0x36`。固件只读取状态，不把数据接入 DM442 的 PUL/DIR 控制：

- `ENC,<axis>,S` 读取轴 0–5 的单行诊断快照；
- AS5600 是单圈绝对编码器；固件的多圈角仅是在本次运行期间按跨零点变化累计；
- 展开算法要求相邻成功采样之间的运动小于半圈；掉线或转速过高时多圈累计可能失真；
- 断电、复位、I²C 长时间掉线后，多圈圈数不可恢复，机械系统必须重新回零；
- 电机附近长线 I²C 抗干扰能力有限，应缩短线长、正确共地和配置上拉，必要时使用
  差分 I²C 延长器；不能把该诊断读数当作安全限位；
- PCF8575 地址 `0x20` 仅在固件中预留，当前 PUL/DIR（包括 DIR）均不经过 PCF8575。

`U_I2CMUX` 是 TCA9548A 成品模块 MOCK 插座；`J_AS0`～`J_AS5` 均为
`3V3 / GND / SDAx / SCLx`。所有 AS5600 必须使用 3.3V 兼容模块。I²C 线应尽量短、
远离电机电源和 PUL 线，核对整条总线的上拉总值；长线应改用成品差分 I²C 延长模块。

### 可选 PCF8575 DIR/ENA 预留

`U_IOEXP` 是 PCF8575 成品模块 MOCK 插座，与 TCA9548A 共用 3.3V I²C：

| 端口 | 规划用途 | 引出接口 |
|---|---|---|
| P0-P5 | DIR0-DIR5 未来逻辑命令 | J_PCF_DIR |
| P6-P11 | ENA0-ENA5 未来逻辑命令 | J_PCF_ENA |
| P12-P15 / INT | 预留 | J_PCF_RSVD |

PCF8575 是准双向端口，源/灌电流和上电状态不能按推挽 GPIO 假定。PCB **没有**把任何
PCF 输出硬连到 DM 输入，原生 PUL/DIR 保持默认直连。未来启用时必须先实测 DM 光耦
电压、电流及共阴/共阳接法，再使用经确认的成品开集电极、ULN 类或隔离驱动模块；
PCF raw header 只接缓冲模块逻辑输入。六路 PUL 始终由 ESP32 原生 GPIO 产生。

TCA、PCF 和 AS 模块只能使用 3.3V I²C 上拉。禁止把模块上的 5V SDA/SCL 上拉直接送入
ESP32；若实物模块只能 5V 工作，必须增加成品双向电平转换模块。

## 更新与打样前检查

1. 修改 `MODULE_GEOMETRY` 和模块 pin helper，使其与实物完全一致。
2. 从项目根目录运行 `python pcb/generate_pcb.py`，再运行 `python pcb/preview_pcb.py`。
3. 用 KiCad 8/9 打开 `stepper_carrier.kicad_pro`，重新填充铜区并运行 DRC。
4. 核对全部连接器进线方向、丝印可读性、模块 USB 口和天线净空。
5. 用万用表检查 `VM_MOTOR` 与任何 24 V 线束无连接，3V3/5V/VM/GND 无短路。
6. 只有完成实物尺寸核验、DRC 和电源检查后才生成 Gerber。

## HANDOFF：后装前必须确认

- **真实尺寸**：TCA9548A、PCF8575、AS5600、DRV8871 的长宽、排针坐标、孔位和高度。
- **真实针序**：TCA 主机/通道脚、PCF 主机/P0-P15、AS5600 四线接口、DRV8871 逻辑脚。
- **真实电平**：两块 I²C 模块在 3.3V 下可工作，SDA/SCL 板载上拉确实到 3.3V。
- **地址/跳线**：TCA 与 PCF 的 A0-A2 实际默认状态，不能只依据网店描述。
- **DM 输入级**：每种 DM422/DM442 的光耦电压、电流、共阴/共阳方式及所需成品缓冲模块。
- **当前 DNP**：U_I2CMUX、U_IOEXP、J_AS0-J_AS5、PCF raw headers 均先不装，原生六轴开环不变。
- **分阶段落地**：先验证 TCA+1 个 AS5600，再扩到 6 个；PCF 先空载验证，再接成品驱动模块，最后才通过可恢复线束切换 DIR/ENA。
