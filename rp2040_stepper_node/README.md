# RP2040 four-axis stepper node

This firmware targets the **regular Raspberry Pi Pico (RP2040, no Wi-Fi)**. A
Pico W is unnecessary because the node communicates only through wired RS485.
One Pico controls four DM422/DM442-class step/direction drivers; six nodes can
provide 24 axes without consuming more ESP32 GPIO.

> Integration status: the protocol parser is host-testable, and pulse timing is
> implemented with one PIO state machine per axis. This workstation does not
> have the Raspberry Pi PlatformIO platform, so the Pico firmware build, four-
> axis concurrent timing, STOP executed-count estimate, RS485 turnaround, and
> real DM422/DM442 electrical interface still require remote hardware validation
> before production use.

## Hardware

| Pico pin | Function |
|---|---|
| GP0 / UART0 TX | MAX3485 DI |
| GP1 / UART0 RX | MAX3485 RO |
| GP10 | MAX3485 DE and /RE (tie together) |
| GP2, GP3 | Axis 0 PUL, DIR |
| GP4, GP5 | Axis 1 PUL, DIR |
| GP6, GP7 | Axis 2 PUL, DIR |
| GP8, GP9 | Axis 3 PUL, DIR |
| GND | RS485 module and driver signal ground |

Use a 3.3 V RS485 transceiver such as MAX3485/SP3485, not a 5 V-only MAX485
receiver directly on Pico GPIO. Terminate A/B with 120 ohm at the two physical
ends of the bus and add bias resistors at one location only.

DM422/DM442 inputs are opto-isolated and often require more current/voltage than
a Pico GPIO can supply. Use a transistor or differential line-driver interface
specified for the drive input; do not assume direct 3.3 V GPIO connection is
valid. Keep the drive power emergency-stop chain independent of software.

All pulse outputs start LOW and no axis moves until a valid heartbeat and MOVE
are received. Each pulse train is generated by a dedicated RP2040 PIO state
machine, so serial parsing cannot stretch pulse timing. `delay_us` is the period
between pulse rising edges (100 through 10,000,000 us); pulse HIGH width is
50 us. The ten-second upper bound supports the default rotary configuration at
0.3 deg/s without changing the 32-bit PIO timing representation.

## Build

PlatformIO selects node 1 by default:

```sh
pio run -d rp2040_stepper_node -e pico
```

Set a unique compile-time ID (1 through 6) for each Pico by changing
`-DNODE_ID=1` in `platformio.ini`, or overriding that build flag in a per-node
environment. Upload with the Pico in BOOTSEL mode:

```sh
pio run -d rp2040_stepper_node -e pico -t upload
```

## RS485 protocol

ASCII, comma-separated, one command per LF-terminated line at 115200 8N1.
Only the addressed node responds. Broadcasts never respond, preventing multiple
nodes from driving the half-duplex bus together.

Master to node:

```text
N,<node>,MOVE,<local_axis>,<steps>,<dir>,<delay_us>
N,<node>,STOP,<local_axis|*>
N,<node>,PING
N,<node>,POLL
N,<node>,STDIAG,<local_axis>
N,*,HEARTBEAT
N,*,ESTOP
```

Node responses:

```text
N,<node>,ACK,<local_axis>
N,<node>,OK,<local_axis|*>
N,<node>,PONG
N,<node>,ERR,<reason>
N,<node>,EMPTY
N,<node>,EVENT,STEP,<local_axis>,P,<executed>,<requested>
N,<node>,EVENT,STEP,<local_axis>,DONE,<executed>,<requested>
N,<node>,EVENT,STEP,<local_axis>,ABORT,<executed>,<requested>
```

Progress and terminal events are stored locally and emitted only in response to
`POLL`. The queue holds 24 entries, coalesces progress per axis, drops new
progress when full, and lets DONE/ABORT displace old progress. If it contains
terminal events only, the oldest terminal is displaced to keep memory bounded;
the ESP32 should therefore poll each online node frequently.

The master must broadcast `HEARTBEAT` faster than every 1000 ms (250 ms is
recommended). A timeout aborts every moving axis and rejects new MOVE commands
until a fresh heartbeat arrives. Broadcast ESTOP also aborts all axes. Both
conditions are reported later through POLL and neither broadcast generates an
immediate response.

`STDIAG` validates node/axis addressing and returns `ACK` without generating a
pulse. A physical motion test must use an explicit MOVE command.

