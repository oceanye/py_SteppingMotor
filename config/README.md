# 随仓库分发的步态参数样例

当前四轴驱动为 X42S UART，DM422/DM442 已退役。新安装绑定默认是
`x42s_uart` 的未绑定状态（不会猜测实物ID、不会自动运动）；在绑定页核对
Mup1→ID1、Mr1→ID2、Mup2→ID3、Mr2→ID4 建议映射并保存。
建议减速比：升降1、旋转21.5；升降导程默认1 mm/转仅是待核实值，已有现场配置不覆盖。
旧 `.stepper_axis.json` / `.stepper_calib.json` 不作为 X42S 的标定依据。
默认固件为 `esp32s3_gear_x42s`；无须在日常使用中修改编译宏或启用历史控制。

`gait_params.example.json` 描述本机构的新桌面默认：两模态自动避让，正六边形俯视投影边长 **190 mm**。
两模态的中心距自动按 `sqrt(3)*190 ≈ 329.089653 mm` 派生，无需再输入。

新安装没有 `.gait_params.json` 时，GUI直接使用代码中的 `default_gait_params()`，
**不需要复制样例，也无需点击“应用模式”**。样例不是第二份运行时配置；
回归测试保证样例解析结果与代码默认一致。

桌面只提供 `two_mode_v1` 自动避让，不再提供 `legacy_gain` 下拉、旧增益k、
独立中心距输入或“应用190 mm两模态”切换按钮。四个动作的 HIGH/LOW由后台自动判定。
已有正确两模态配置保留现场尺寸、速度、方向和零位，不因重新启动反复重置。
投影边长在几何参考中用于核实实物，本机构为190 mm；中心距始终由边长派生，
保存时保留完整精度，不把界面舍入值写回模型。
**旧策略（含未记录模式的早期配置）在启动时先备份，再自动迁移至190 mm自动避让**，
并在启动日志中明确提示。不要整份覆盖现场配置。

此样例没有端口、电机绑定、PPR/传动比、旋转零位、标定签名或标定确认。
未确认的腿投影半宽4 mm、杆半径5 mm、安全间隙2 mm沿用既有默认，仍需现场核对。
安装/加载190 mm默认不等于实机校准完成；程序不会因此自动发出运动命令。

## 旧配置的启动自动迁移

2026-10-19 早间上传的现场日志仍记录 `legacy_gain`、腿长40 mm、中心距220 mm；
这不是本机当前配置。更新本版代码并重启GUI后，旧策略会自动迁移，不再要求手动切换。
本机构目标为：`trajectory_mode=two_mode_v1`、`arm_length_mm=190.0`、
`d_mm=sqrt(3)*190≈329.08965343808666`。HIGH/LOW按当前站位、横梁扫掠自动选择，
不是由操作员分别加载两份配置，也不是固定绑定到某个动作按钮。

1. 确认电机停止，保存需要保留的现场输入，正常关闭GUI；更新后重新启动。
   迁移在串口未连接、GUI尚未构建时进行，以旧文件为基础，不发送电机指令。
2. 查看启动日志：正常190 mm两模态配置直接使用；旧策略应显示“已自动迁移”，
   不再出现选择旧策略或手工应用模式的步骤。
3. 原文件逐字节备份为项目目录的 `.gait_params.json.backup-<随机串>.json`。
   备份或保存失败会保留旧文件，内存只提供未标定的190 mm自动避让用于离线评估；
   保存和实机启动会被阻止，修复文件问题后重启重试。绝不回退运行旧策略。
   这些备份与本机配置一样忽略，不上传仓库。
4. 旧策略迁移改变模式、边长与派生中心距，清除 Mr1/Mr2 零位、零位签名及标定确认/指纹。
   保留初始选格/摆放、方向、速度、行程和其余几何参数；不改变电机绑定、PPR、
   减速比、导程或驱动器自身零点。已正确使用两模态的文件不重复迁移、不额外清零。
5. 重新核实腿投影半宽、高杆投影半径及安全间隙。日志中的 **0.2/0.2/0.1 mm**
   原样保留而非认定正确；默认的4/5/2 mm也不是实测证明。必须根据实物修正，
   不可为通过评估而缩小包络。
6. 核实方向/传动与支撑，将机构摆回所选起点/低节点基准，连接并使能四台。
   点击步态页 **确认摆放并记录双侧基准（首次/恢复）** 一次，程序读取两侧实际角度，
   整体保存基准和确认，无需分别记零、再勾选或再次保存；常规GUI不再提供驱动器ZERO。
   四个动作分别评估，再在现场保护措施下低速分阶段验证。

13:51的最新现场会话已完成190 mm自动迁移，但后续出现重复记零/确认与运动前取消后
被要求恢复的问题。新流程见 [X42S步态基准准备与标定简化](../docs/HANDOFF_2026-10-19_BASELINE_WORKFLOW.md)。
正常连续换步无需重新记零；调整运行速度/行程或预览采样不清除基准确认。
断电后必须核对物理摆放和驱动器坐标连续性，PC文件持久化不等于硬件绝对坐标保持。

启动日志 `configuration.loaded` 应包含 `two_mode_v1` 和190；新保存的
`configuration.gait_saved` 还会写入完整精度的派生中心距。
仅看190或仅看界面的HIGH/LOW标签不能确认完整迁移。
备份恢复需要关闭GUI、保留当前文件后将选定备份复制为 `.gait_params.json`；
重启仍须重新建立并核实实机基准，不能把恢复旧标定当作安全证明；恢复旧策略文件会再次自动迁移，
不是重新启用旧模式的方法。底层历史公式/解析仅保留供离线分析和回归对照，非GUI可选运行策略。
