# X42S 步态基准准备与标定简化

适用机构：投影边长190 mm、四台X42S、HIGH和LOW自动避让。常规准备统一为
**摆好实物 → 确认摆放并记录双侧基准 → 选择动作**。不需要驱动器归零，
不需要分别记两次零、再勾选确认、再保存。正常连续换步沿用同一基准。

## 三种不同的操作

| 操作 | 作用 | 何时需要 |
|---|---|---|
| 方向与传动参数核对 | 确定X42S ID、减速比、导程、正方向；不做旧脉冲轴PPR标定 | 首次装机、更换或修改相应硬件参数 |
| 双侧步态基准记录 | 把当前实测旋转角保存为低节点姿态参考，并确认所选起步位置 | 首次准备、迁移、异常恢复或物理坐标关系改变 |
| 驱动器ZERO | 当前实现为93命令：存储电机单圈回零点，不清多圈计数；实机可能自动使能，见10月23日记录 | 不是本工作流前置，常规GUI入口已移除 |

X42S基准保存的是 `实测电机角 / 减速比`，不要求读数为0。
例如当天10:34会话中的Mr1约−5.014°、Mr2约−23.037°，也可以作为PC基准。
程序以当前读数和基准的差值还原姿态，不需要把驱动器内部角度强行清零。
升降轴仍以当前位置和相对行程执行，不新增升降归零步骤；真实支撑高度必须人工核对。

## 首次装机和首次准备

1. 在“电机绑定与状态”页核对四角色与驱动器ID、减速比、升降导程。
   当前现场旋转减速比为21.5；升降导程必须以实物为准，不能把默认值当作实测值。
   在机构可靠支撑、不会扫杆的条件下低速点动确认方向并保存。硬件未改变时不重复此项。
2. 连接控制器，点击“使能全部”，等待四台在线、无保护故障、到位静止且位置数据新鲜。
   在线/使能/遥测错误不是标定错误，不要为此改零点或方向。
3. 在步态页核对190 mm、真实腿/杆投影半宽和安全间隙；选择与实物一致的起步两格或红杆侧。
   将左右足人工摆到相应支座，三爪均对准低节点，确认支撑可靠。选择地图格子本身不移动机构。
4. 点击左栏 **确认摆放并记录双侧基准（首次/恢复）**，阅读摆放条件后确认一次。
   程序检查状态，读取两侧角度，整体保存基准、签名与确认；成功前不发布任何半成品基准。
   此按钮不发送MOVE、EN或ZERO，不改变方向或脉冲位置账本。不必再点保存。
5. 选择四种动作之一并开始。HIGH/LOW由后台决定，仍做相位、碰撞、速度、分辨率和线缆窗口检查。
   新装机应先用S0至S7分阶段低速验证；“一键执行”不是取消这些预检或替代实机验收。

记录失败时旧基准不变：先处理弹窗指出的离线、失能、运动、遥测或磁盘问题，
再重试同一个按钮。无需重新做方向试验，也无需驱动器归零。

## 正常连续运行

同一GUI会话中，完整完成一步后直接选择下一动作。不要再次点击双侧基准按钮，
它表示“实物已经回到所选起步位置”，会重建地图坐标，而不是普通下一步按钮。

- 改速度、抬足行程、线缆角度窗口或预览采样：不清除基准确认；启动仍重新校验新计划。
- 改方向、传动、起步坐标或几何参考：按界面提示核对实物后重新确认，不自动认定旧基准有效。
- 在S0、S1或运动阶段尚未排队前取消：只取消计划，保留基准，可直接换动作。
- 运动已排队、开始或曾执行过运动阶段：中止仍停车并要求恢复，不能按“还没看见动”跳过。
- 完整完成后清理流程显示：不重新标定。模拟和地图显示旋转不代表实机重新摆放。

## 中止和断电之后

运动中止、碰撞、失能滑动或位置不可信后，先保证支撑、确认全部停止并解除故障。
将实物恢复到所选起步两格和低节点姿态，然后使用同一个双侧基准按钮一次。
方向和传动没有变化时无需重新做四台方向测试。不能仅凭角度读数就确认足已可靠落地。

PC文件保存了基准，**不代表驱动器断电后保持同一多圈坐标**。
重启或断电后应核对坐标连续性及真实站位；不能确认时重新摆放并记录一次双侧基准。
当前实机连续步的站位账本主要在会话内，不能把“重启后读到旧标定文件”理解为自动恢复中途行走位置。
若实物不在原起步格，应先选择符合实物的相邻起步格和低节点姿态，再建立基准。

## 不应靠重新标定解决的问题

| 提示 | 应做的事 |
|---|---|
| 四台未接齐、未使能、离线 | 检查ID、连接、供电与使能；保留方向和零位 |
| 遥测不新鲜 | 等待新样本、核查PC和固件版本及轮询；不要将旧样本当新样本或调大门槛绕过 |
| 腿与高杆间隙不合格 | 核实投影模型、真实包络和姿态，不缩小尺寸或重记零强行放行 |
| 线缆角度窗口越限 | 不得通过重新记零隐藏缠绕量；先核查并安全解绕，再建立真实基准 |
| 支撑足相位不匹配 | 核对实际落脚、所选格、方向和编码器坐标；不是直接点“已确认” |
| 基准保存失败 | 处理文件权限、磁盘或迁移备份问题；旧基准仍保留 |

X42S当前仍为顺序MOVE近似同步，日志固定“约15 ms”不是逐次实测值。
本次不修改避让公式、X42S同步协议、硬件限位或遥测新鲜度阈值。
后续DM残留清理已修改固件默认环境/旧脉冲隔离，并修正孪生到位后误判忙碌，见下节。
灰色曲线仍为计划参考；本次没有接入外部间隙实测曲线。

## 变更与离线验证

双侧基准记录在保存成功后一次性发布；任何一轴状态无效、控制命令在途、
急停、关闭、旋转释放、连接/绑定变化或写盘失败都会拒绝，保留旧基准与恢复要求。
记录期间阻止新控制工作线程，步态占用期间阻止X42S手动写命令，避免从另一页破坏基准。
普通保存和启动只沿用已有硬件确认签名，不自动替换为新绑定/传动的签名；
硬件变化后必须经明确的双侧基准确认流程重新签名。

GUI不再提供单侧记零加独立复选框的常规路径，也不再显示“M5未过所以一律拒绝”的旧说明。
流程指引可从标定页的“查看首次准备与日常运行指引”打开。

测试覆盖真实非零角度换算、一次保存、部分读数失败、过期/缺失/非有限数据、
写盘失败、控制并发互锁、运动前取消、运动后恢复、参数编辑和隐藏Tk界面。
所有串口测试使用替身，没有连接或驱动实机。远端需复测首次准备、四动作、连续两步、
运动前取消、运动中止及断电后的坐标核对。

标定简化阶段完整回归：`python -B -m unittest discover -s tests -q`，610项全部通过，
约181秒，包含真实Tk隐藏界面与新按钮联调。未烧录或执行实机运动。

## DM422/DM442 退役后的默认配置与隔离

当前主控制链为 PC → ESP32-S3 → TTL-UART → 四台X42S。
DM422/DM442已经替换，不再作为正常GUI入口，也不再要求它们的PPR/原点标定。
已有正确X42S绑定、减速比、导程、方向和基准保持原值；不会因本次更新自动重新标定。

| 层 | 当前行为 | 历史内容如何保留 |
|---|---|---|
| 固件 | 默认 `esp32s3_gear_x42s`；旧脉冲GPIO/任务不初始化；旧MOVE/SYNC/ENA/STDIAG/ENC/NODE明确拒绝 | `esp32s3_gear` / FOC / remote环境仍可显式构建 |
| 桌面 | 默认X42S未绑定；30轴/Pico页隐藏，旧轴配置/校准文件不加载；旧脉冲发送拒绝 | 仅历史机器维护者显式设置 `STEPPER_LEGACY_STEPDIR=1` 后重启GUI开放，不用于当前机器 |
| 网页 | 四角色状态保留，30轴历史区默认隐藏；旧运动/配置API拒绝 | 停止与全局急停不删除；当前网页仍不提供X42S步态启动 |
| 文档/PCB | 使用本说明及 `user_guide.html` 顶部当前指引 | 旧接线图、板图、BOM和生成器标为历史，不能当当前X42S制板依据 |

旧STEP/DIR绑定文件只读保留并提示迁移，不自动把旧轴号猜成驱动器ID。
操作者选择X42S，核实台号及传动参数后保存，首次记录双侧基准一次。
建议映射仍是Mup1→1、Mr1→2、Mup2→3、Mr2→4；旋转默认21.5、升降默认1，
导程1 mm/转是软件默认值，必须与现场实际丝杆一致。已有参数不会被建议值覆盖，除非主动填入并保存。

`X42S_PULSE_PER_REV=3200`及相应steps字段仍是当前UART命令换算的一部分，
不是DM残留；不能批量删除“step/pulse”或改成旧轴PPR。
固件仍报告GEAR模式，因为它复用独立GEAR/轨道D子系统；这不意味着四角色使用DM驱动。

### 数字孪生与状态来源

- X42S位置为驱动器电机轴反馈，经减速比/导程换算到旋转°及升降mm。
- 目标值到位后仍可能非空，不能据此判断正在运动；现在结合reached、速度和遥测可信度判断。
- 地图世界姿态、支点关系和高杆间隙仍按模型推算；驱动器编码器不能证明接触、打滑、杆件挠曲或真实空间间隙。
- 灰色曲线为跨步计划参考，不再显示“编码器未接入”的笼统旧说明，也不伪造成间隙实测。

### 问题与修复

- 顶部默认“模拟”与地图默认“实机”原为两个独立变量，操作组、绘图和曲线可能不一致。
  现在共用一个模式变量；大小窗口同步。切到实机浏览会暂停模拟，返回可继续。
  实机正在执行时强制展示实机并锁定模拟，保留中止入口。
- 原“应用起步位置”无论显示何种模式都修改实机参考并作废标定。
  现在区分【应用模拟起点】和【应用实机起步位置】，两组分别保留待选两格。
  虚拟应用只重置模拟，不保存现场配置、不归零、不移动电机。
  实机应用仍需静止检查与人工确认，之后只需一次双侧基准记录。
- 遥测未知/过期原先会把纯模拟也取消并切回实机。
  现在未知状态仍禁止修改实机参考，但不等同于存在运动指令；允许独立离线模拟。
  本机执行占用、控制任务以及明确运动反馈仍锁定模拟，未放宽实机启动预检。
- 选点/下拉框改变后提示“待应用”；未应用时不允许悄悄沿旧起点走步。
  不相邻/同格/超出5×5地图、参数无效与间隙校验失败均提供原因。
  模拟中禁止改起点；取消本步保留已完成站位，重置才回所选起点，清路径不改站位。
- 曲线累计超过90秒后，旧窗口右端等于当前时刻，导致下一候选全部被裁掉。
  现在维持90秒宽度，为候选/执行中模拟计划预留最多30秒前视；不重置累计时钟。
  抬升阶段也显示当前步灰色计划，进入S4后彩色模拟数据逐渐覆盖；纵轴仍为−20～200mm。
- 实机灰色计划之外，增加可信、新鲜四轴X42S反馈的距离模型彩线；按同一S4模型进度对齐。
  过期/断连停止采样并断开线段，换步归档，清路径同时清曲线；大小窗口不重复采样。
  **彩线是轴位反馈推算的爪端–杆表面距离，不是外部间隙实测，也不能代替整腿扫掠校验。**
- 周期刷新即使出现一次显示异常也继续调度，异常仍由原日志系统记录，避免整个状态区永久冻结。
- 更新 `scripts/gui_smoke.py`，不再测试已移除的旧预览按钮，使用真实完整Tk界面、临时配置和
  190mm默认参数测试四动作模拟/暂停/继续/曲线。禁止打开串口，不改现场配置。

### 使用与验收

1. 重启 `run_gui.bat`，打开三足步态，默认进入模拟组。
2. 通过下拉框或“地图选左足/右足”选择相邻两格，点【应用模拟起点】。
   仅模拟分析不需要重新建立实机基准。
3. 点选四种动作查看虚线落点/灰色候选曲线，点【模拟下一步】演示完整阶段。
   完成后直接继续，位置和90秒曲线跨步累计；地图仅保留当前深色、上一步淡色路径。
4. 切到实机组后，核对该组起点与实物。确需改变物理起点时才应用实机起步位置并重记双侧基准。
   真实驱动测试由现场负责人在可靠支撑和可急停条件下完成。
5. 离线命令（需Python具有Tk和pyserial）：

### ACK与实测到位的具体约束

手动MOVE从下发到确认实测终点期间保持待完成标记；正常ACK只更新“已接受”，不代表到位。
终点核验使用发令前可信电机轴位置加本次脉冲折算角，收到ACK后至少经过0.45s前沿保护，
新样本必须reached=true、位置新鲜、已使能、无故障，且误差不超过2脉冲对应的电机轴角
（0.225°，含0.1°上报量化）。无速度字段可以接受，但有非零速度不能接受。
若发令前没有可信原点、ACK丢失或终点不能确认，继续保持待完成；请现场确认后点【停止】，
收到精确STOP应答即可结束待完成状态，无需强行归零。停止不等于可靠落地，支撑仍需人工确认。

双升降仍是顺序MOVE，不是驱动器硬同步；界面明确标注。未改现有自转/公转轨迹公式、
HIGH/LOW选择、驱动器协议或固件时序，不用缩小投影尺寸/安全间隙来换取测试通过。

### 结论与已确认缺陷

这不是一个“把 HIGH/LOW 翻一下”就能解决的问题。已确认至少四条独立故障链：

1. **规划与画面不同系**：远端已把中心/高杆几何改为 `dir(a)=(cos a,-sin a)`，
   但实时地图的高杆、三腿、候选、历史路径、距离曲线仍多处使用 `+sin`。
   所以 GUI 里的高杆侧和腿扫掠不一定是规划器检查的那条路径。现在全部使用同一世界定义，
   模型与 GUI 的高杆坐标、每条腿端点以及整腿间隙均有交叉测试。
2. **动作与标签错配**：界面默认 L+ 而内部是 +60°；忙碌回退/开始执行后回填仍用旧映射，
   同时“红杆在左/右”的标签没有随镜像改变。现统一 L+/R+→−60°、L−/R−→+60°；
   红杆侧由“从左足看向右足”的有向横梁和共享高杆叉积计算，用户不选模态。
   还修正旧默认右侧示例的起始方位 60°→300°，确保它确实从 B 绕 C 到 A。
3. **理论轨迹与驱动不等价**：X42S 是立即执行的独立梯形 MOVE，不能用15ms说法证明
   两轴全过程共享五次进度。现沿原 LOW/HIGH 角度路径细分，每段认证整个双轴进度矩形，
   覆盖任一轴先走完的情形；段间核验实际终点再发下一段。并未重写驱动协议或固件。
4. **到位/故障/恢复不可靠**：旧 reached 或 MOVE ACK 可提前结束；顺序等待可能延后发现
   Mr2 故障；小于30单位的自动回位没有扫掠证明，且只收到 ACK 就恢复账本。
   现在完成必须匹配本条预约/目标、新样本、静止及2脉冲容差；双轴公平轮询，越界/掉线/故障
   中止组并请求全部停车。STOP 需精确应答，失败锁定“停车未确认”；恢复入口只读核验，
   禁止没有避让认证的自动直返，不能以“小位移”认定安全。
   不只检查当前运动的轴：任一步态占用轴（包括静止支撑/升降轴）明确离线、失能或故障，
   也会阻止后续下发并中止组等待；不把该轴当前不动当作忽略故障的理由。

另外完成：短暂遥测失信冻结/恢复、量化抖动容差、实测/历史/计划最低值分离、
跨轴时间差提示、持续显示 S4 组进度、清路径保留步数、完成站位账本一次性更新。

### 两种摆放与四种动作（当前模型，不固定绑定模态）

世界 x 向右、y 向上；模型角顺时针为正；公转参数满足 `Δβ=−φ`。
两模式共享 `Δq支撑=φ`、`Δq摆动=Δψ+φ`；LOW 的 `Δψ=2φ`，
HIGH 为相反符号的120°平滑陡化折线（指数18，保留原路径）。
电机输出轴命令再分别乘 `mr1_sign/mr2_sign`，不能把世界自转、关节角、公转混为一个角。
先看实际横梁扫掠扇区是否含高杆，再选 HIGH/LOW，最后认证整腿连续扫掠；
“横梁不跨高杆”也不免除腿的检查。

|---|---|---|---|---|---|

### 停车确认与恢复

`motor_control/x42s_safety.py` 独立实现全局ESTOP反馈核验：

1. 先锁定普通运动、作废旧任务代次，发送ESTOP。精确 `OK,ESTOP` 只表示网关已处理。
2. X42S后端须四角色唯一绑定；在3秒有界窗口内轮询四台，不发送MOVE/ZERO/EN。
   每台须在线、失能、有实际位置；年龄不超过1500ms，采样时刻晚于本次ESTOP。
3. 每台须两份不同采样时刻的反馈，至少相隔100ms，位置差在对应角色容差内；
   若有有效速度，绝对值须≤0.01RPM。允许已失能的驱动保留故障位，不要求reached。
4. 只有四台均满足且绑定/控制代次未变化才清除“停车未确认”与手动在途预约。
   缺失、旧数据、仍使能、漂移、非零速度或错误ID均不放行。

连接时即使只拿到网关ACK，也保留串口用于诊断，但运动仍锁定；检查现场后可点击
顶部 **急停并核验** 重试。断开失败时恢复重试入口，不再永久停留“正在断开”。
硬件急停释放也不会自动解锁，需再次核验。网页同步区分“指令应答”与“停车核验”。
这是有限采样下的**观察到静止**，不是机械制动、足部承重或整个机构安全证明。
失能后有下滑风险的机构必须先提供可靠支撑；失联时软件无法保证停车。
轨道D没有新增编码器确认，仍采用固件原有停车应答，不能当作轨道的实测静止证明。

### 升降容差与避让预算

统一函数 `x42s_motion.endpoint_tolerance(role, binding)`，单位是**电机轴度**：

- Mr1/Mr2：仍为2脉冲，即 `720/3200 = 0.225°`。
- Mup1/Mup2：`max(0.225, min(1.0, 0.002 × 360 × gear_ratio / lead_mm))`。
  默认1mm导程、减速比1时为0.72°，相当于0.002mm；1°上限防止随减速比无限放宽。
  对粗量化绑定，0.225°下限可能对应大于0.002mm，不能把0.002mm称为所有配置的硬上限。
- 到位还必须满足本条命令所有权、新鲜反馈、实际目标、reached/在线/使能/无故障及
  有效速度检查。手动点动、步态到位和越界判定复用同一角色容差，不是“收到ACK就完成”。
- 升降起点和终点两端的残差都换算为mm，纳入避让误差预算。不能靠改容差绕过
  高杆扫掠检查；位置偏差超过边界、stall或掉线仍中止。旋转控制律与分段认证不变。

- 直线：`h_mm = motor_deg × lead_mm / (360 × gear_ratio)`。
- 旋转：`q_output_deg = motor_deg / gear_ratio`；本机21.5倍减速。
- 逻辑脉冲：`N = motor_deg × ppr / 360`。X驱动最终角度指令另有0.1电机°量化，
