# 两类模态、四种换位：三足腿—高杆协同避让

日期：2026-09-23。基线：Gitea `main` 的 `d5a12fa`。
审核分支：`codex/gait-two-mode-avoidance-2026-09-23`。

## 1. 本次完成的范围

用户说的碰撞是**三条腿扫到高杆**，不是横梁或中心结构碰杆。
本次将两类候选角度轨迹接入：GUI 四种动作 → 当前站位分类 → 同一分段规划 →
腿—高杆连续间隙校验 → 双轴原子 SYNC 实机执行 → 脉冲数字孪生。

- 不是仅干跑；S4 会通过既有串口、预约、进度和 DONE 链路驱动真实旋转轴。
- 本机只做离线验证，没有连接电机、烧录固件或验证负载下的避杆。
- 不合并主线；远端负责人审核、现场验证后合并。
- TMC2209 支线不合并、不恢复；8765 服务不启动、不改动。
- 本地机器配置不提交；不把测试用的细腿尺寸当作实测数据。

## 2. 模型边界与坐标

采用需求中的紧贴正六边形晶格：中心距 `d=√3R`，R 为中心到落脚点的径向长度。
低杆相位为 `30°+120°j`，高杆相位为 `90°+120°j`。相邻六边形共享顶点。
腿按从中心到 R 的径向线段加等效半径建模，根部不作忽略；相比旧壳边到腿端模型更保守。

这不是另一种“只有末端竖直支腿”的模型。若实物只有末端与高杆高度重叠，需另作
三维包络验证，不能擅自把径向腿模型改成三个无厚度点来放行。

角度约定延续主线：

```text
φ > 0：俯视公转顺时针；φ < 0：逆时针
β = β_start - φ                         横梁世界方位
ψ = ψ_start + Δψ                       摆动三足世界相位
Δq_swing = Δψ + φ                      摆动电机关节角
Δq_support = φ                         支撑电机补偿角
```

“同向／反向自转”比较的是世界坐标下的 ψ 与公转，不是直接比较两个电机 DIR。
现场 `mr1_sign/mr2_sign` 在转换电机轴坐标时再应用。

## 3. 两类模态如何自动判断

每次取**当前支点到摆动端的方位** θ，以及本次带符号公转弧 φ_end。
公转扇区中分方向 `m=θ-φ_end/2`：

- `m ≡ 30° (mod 120°)`：公共低节点侧 `low_junction`。
- `m ≡ 90° (mod 120°)`：公共高节点侧 `high_junction`。
- 仅允许相邻支座 `±60°`；对齐容差 0.5°与既有脉冲站位预检一致。不合法不猜测模式。

初始左足 A、右足 B 时：

| 按钮 | 摆动／支撑 | 路由 | 模态 | 世界 Δψ | Δq摆／Δq支 |
| --- | --- | --- | --- | --- | --- |
| 左顺移 | 左／右 | A→C，绕B | 低节点侧 | +120° | +180°／+60° |
| 右逆移 | 右／左 | B→C，绕A | 低节点侧 | −120° | −180°／−60° |
| 左逆移 | 左／右 | A→邻座(0,-1)，绕B | 高节点侧 | +120° | +60°／−60° |
| 右顺移 | 右／左 | B→邻座(0,-1)，绕A | 高节点侧 | −120° | −60°／+60° |

这些分组**不能永久绑定按钮**。例如左顺 A→C 完成后，从 C/B 站位右顺 B→A
属于低节点侧，不是初始 R+ 的高节点侧。障碍邻域也随新支点重建，避免漏查外侧邻杆。

## 4. 自转规律与实际执行路径

令 `u=φ/φ_end∈[0,1]`，σ 为 φ_end 的正负号。

### 4.1 低节点侧

`Δψ=σ·120u=2φ`，世界自转与公转反向；一条原子 SYNC 即可准确执行。

### 4.2 高节点侧

生成曲线：

```text
F(u) = u^6 / (u^6 + (1-u)^6)
Δψ = -σ·120F(u)
```

世界自转与公转同向，前后段少转、中段集中调相。不是把固定 k 从 +2 改成 −2。
终点三重对称等效不能证明中途避杆；本实现检查全扫掠。

**实际执行不是直接运行这条连续公式**：在 u=0,1/60,...,1 取 61 个节点，形成
60 段角度折线。每段 `(Δq摆,Δq支)` 由一条共享五次时间进度的 SYNC 执行，
两轴段末停稳，再下发下一段。预览、间隙校验使用的都是这条实际角度折线，不偷用更光滑的理想曲线。

这意味着有段间停顿及串口往返开销，不是无停顿轨迹流。后续如改为固件缓冲流，必须重新验证
插值、速度、换向和中止，不能直接去掉等待 DONE。

以左逆为例，摆动关节终点虽然是 +60°，中途大约先到 −18.2°、再到 +78.2°、最后回到 +60°。
因此必须允许运动中换向，必须检查**全部分段端点**的行程/线缆窗口，不能只检查最终 +60°。

段时间满足：

```text
T_i >= max(0.05s,
           1.875·|Δφ_i| / 公转峰值速度,
           1.875·|Δq摆_i| / (3·公转峰值速度))
```

每段同时保留固件 5000pps 峰值及 120s 单段时间限制；速度、分辨率不合格直接拒绝。
总时长是分段时间之和，不含主机/串口停顿。界面动画表示空间扫掠，不是等时钟的负载仿真。

## 5. 腿—高杆校验与执行门槛

对所有三腿和邻域高杆求水平净间隙：

`D = dist(腿中心线段, 高杆轴线) - 腿半径 - 杆半径 - 安全间隙δ`。

检查至少 600 个公转采样并显式加入全部执行节点。每相邻采样区间扣除
`(d·|Δφ| + R·|Δψ|)/2` 的运动界（角度换为弧度），得到连续间隙保守下界。
每个区间内相位线性，因此这个界覆盖段间扫掠，不只检查起点、中点、终点。

- 模型净间隙 ≤0：新模式在任何抬腿运动前拒绝。
- 仍须覆盖脉冲取整、双轴进度量化、初始相位/横梁误差及直轴量化包络，否则拒绝。
- S3 如需原地相位纠正，也按腿—高杆平面扫掠检查。
- 抬升高度不能让新模式的腿平面冲突被忽略；提高 lift 不会改变该项校验结果。
- 报告显示模态、净间隙保守下界、采样最紧腿、杆标识和公转角；最紧采样角不是首次接触角。
- 结构三维间隙仍可作为附加诊断；**新模式通过不代表横梁、壳体、线束等全机碰撞验收通过**。

当前默认 R=40mm、腿半径4mm、杆半径5mm、δ=2mm 都是占位值；按它们的新模式
净间隙为负，是正确的拒绝结果。禁止为得到绿灯而调小半径、把腿当点或伪造现场数据。
实际腿／杆很粗时，这两条候选可能无足够间隙；软件不会声称所有机构必有解，也没有全局最优搜索。

## 6. 脉冲一致性、异常和数字孪生

- 分段节点都相对 S4 开始的同一原点换算脉冲，绝对累计取整后求相邻差值，避免 60 次独立取整累积漂移。
- 每个节点预检包含中间极值和物理方向符号。
- 某段一个轴取整为 0 脉冲时，仍作为 SYNC 成员预约、等待其 `DONE,0,0`；不丢掉一半同步组。
- 两轴都没有有效脉冲、或脉冲误差已超过间隙时拒绝，不静默跳段。
- 任何 ABORT、断连、丢 ACK、超时、非完整 DONE 都禁止后续段/落脚；停止本步四轴并要求人工恢复。
- 整个 S4 只建立一次旋转原点。每段进度更新累计世界位置，孪生不在每段重置到 φ=0。
- 邻座作下一步支点时可解析其归一化晶格坐标；视图按本次路由定框，不裁掉下方邻座。
- 无编码器：画面来自已报告脉冲，不是实测位置，不检测失步、打滑或实际杆接触。

ESP32 沿用 `SYNC V1` 文本协议，不新增指令，也不把两条独立 MOVE 冒充同步。
固件小修：两轴恢复可接收下一段后才发布终态，且先缓存本段总脉冲数，避免主机紧接下发
下一段时读到旧忙状态或新任务覆盖旧终态数据。应将该固件修正随桌面版一起验收。

## 7. GUI 与旧配置迁移

运行页新增轨迹模式：

- `two_mode_v1`：本次两类模态自动避杆，新建桌面会话默认选择。
- `legacy_gain`：保留旧固定 k 行为。旧配置没有 trajectory_mode 字段时按此读取，
  不静默把远端已经运行的 k 值改成新轨迹。该模式原有碰撞“仅提示”行为保留，**不具有新模式避杆保证**。

远端升级步骤：

1. 备份 `.gait_params.json`、`.stepper_axis.json`、`.coordinated_bindings.json` 和 `.stepper_calib.json`。
2. 审核分支后更新软件；按现场固件构建变体验证/更新 ESP32。不要改刷成另一驱动或 TMC2209 支线。
3. 在步态运行页主动选 `two_mode_v1`。旧 k 字段保留但此模式忽略它，不要求用户手动选择模态。
4. 新模式使用紧贴几何 `d=√3R`，旧中心距保存值保留、不参与新模式规划；若现场不是这种布局，不得选择此模型。
5. 核实杆高低朝向和三足低节点零相位、腿／杆半径、R、δ；核实四轴方向、PPR、减速比和直轴导程。
6. 更换模式/参数会撤销确认并使旧预览失效。先完成现场标定和站位确认，再勾选确认。
7. 分别预览四个动作：应看到当前模态、同步腿相位、邻杆和净间隙结果。未通过不要实际开始。

配置文件均被 Git 忽略，不随提交覆盖现场配置。纯 Python API 的 `GaitParams()` 仍默认 legacy，
这是兼容旧调用者；新桌面初始化显式选择 two_mode。
