接线检查表 · ESP32-S3 + 6×DM422/DM442 + 2×GEAR + 轨道 D

对应 esp32s3_gear / DRIVE_MODE_GEAR · 固件引脚源：esp32_stepper/src/config.h · PCB 接口源：pcb/README.md

DM 驱动专用 24V（板外） VM_MOTOR（按电机额定电压） 3.3V 逻辑 公共 GND 禁止误接
PCB 仍是 MOCK 机械版本。当前板框为 180 × 210 mm；ESP32-S3 DevKit、3 块 DRV8871、TCA9548A、PCF8575、RS485 模块、端子和安装孔都只是参数化占位。打样前必须按实物测量外形、排针中心距、孔位、插装方向和引脚顺序，并更新 pcb/generate_pcb.py 顶部的 MODULE_GEOMETRY。当前文件只确认电气目标，不代表机械尺寸已经定版。
DM422/DM442 的 24V 绝不进入模块化 PCB，也绝不接到 N20、轨道 D 电机或 DRV8871。六套 DM 驱动的 24V 必须由板外、额定电流足够且带保险的成品分配模块供电。三块 DRV8871 只接独立的 VM_MOTOR 低压电源；VM 电压以实际电机和模块额定值为准，不再假定固定 12V。

5. 独立轨道 D（第 3 块 DRV8871）

轨道 D 是开环直流电机，不占用两路闭环 GEAR 轴，也没有编码器接口。它通过 U_DRVD 控制前进、后退和停止。

  • Pico/RP2040 UART 使用 3.3V 逻辑电平，TX 与 RX 交叉连接，双方 GND 必须连接。
  • 编码器模式使用 TCA9548A 隔离 6 个固定地址 0x36 的 AS5600；PCF8575 不能代替 TCA9548A。
  • PCF8575 只用于 DIR、ENA、限位等低速扩展，不用 GPIO 扩展器实时生成 PUL，当前也不接管原生 DIR。
  • 外部 Pico 同时接自己的 USB 时，不再从 J_AUX_UART 的 5V_USB 反向供电；只保留一种供电路径。
  • 直接 TTL UART、编码器/PCF I²C 与 U_RS485 共用 GPIO42/47，正常装配三选一；TCA 与 PCF 可在同一 I²C 模式内并存。
  • U_RS485 只装 3.3V 逻辑兼容的成品模块；A/B/GND 从 J_RS485 出板。
  • RS485 长线时的终端电阻、偏置和拓扑按所选成品模块及现场总线设计，不在当前 MOCK PCB 中假定。

8. 公共 GND 与线束检查

使用额定电流足够的成品地线分配端子，把以下各点接到同一参考地：

  • ESP32 / 模块化 PCB 的 GND。
  • DM 专用 24V 电源负极及板外保险分配模块负极。
  • 六套 DM422/DM442 的 V-、PUL- 和 DIR-。
  • VM_MOTOR 独立低压电源负极。
  • U_DRV0、U_DRV1、U_DRVD 的 GND。
  • J_ENC0、J_ENC1 的 GND。
  • 如使用 AUX/Pico/RS485，其 GND。
断电后用万用表通断档确认上述 GND 两两连通。不要用“测得 0Ω”作为不同电源正极可以并联的依据；所有正电源仍必须严格分域。

9. 打样与装配前检查

机械与模块核对

  • 实测 ESP32-S3 DevKit 是 2×22P，排距、总尺寸和 USB/天线方向与 U1 占位一致。
  • 实测三块 DRV8871 的外形、排针中心、孔位及 VM/GND/IN2/IN1 顺序。
  • 实测 RS485 模块布局；不确定时不焊 U_RS485，只保留 J_AUX_UART。
  • 端子进线面朝板外且不会与模块、螺钉、外壳或线束干涉。
  • DevKit 天线 keepout 内没有铜、线束、螺柱或大块金属遮挡。

断电电气核对

  • DM 24V+ 只到板外 DM 驱动分配，不进入 PCB 的任何端子。
  • J_VM_IN 正端只接实际电机允许的 VM 电压，不与 24V+、5V_USB、3V3 连通。
  • 公共 GND 全部连通；每个 DM 的 PUL-/DIR- 均到 GND。
  • 3V3 ↔ GND、5V_USB ↔ GND、VM_MOTOR ↔ GND 均无明显短路。
  • 六组 PUL/DIR、两组编码器、三块 DRV 的 GPIO 与 §2 完全一致。
  • 轨道 D 明确为 GPIO40/41；AUX 明确为 GPIO42/47/48。

10. 安全上电顺序

  1. 架空所有机械负载或确保运动范围无人、无线束和硬限位碰撞；准备可立即切断 DM 24V 与 VM_MOTOR 的物理开关。
  2. 保持 DM 24V 和 VM_MOTOR 关闭，先给 ESP32 接 USB。
  3. 连接 PC GUI / 网页服务后立即执行全局停止，确认固件处于 GEAR 模式且没有待执行命令。
  4. 先开启 VM_MOTOR，确认三块 DRV8871 与电机都静止、无发热和异常电流。
  5. 再开启板外 DM 专用 24V，确认六套驱动器状态正常且步进电机没有意外运动。
  6. 首次仅用最低合理速度/占空比，逐轴点动；一次只验证一个执行器。
  7. 最后验证轨道 D 前进、停止、后退及租约超时停止，不要从高速直接反向。

11. 首次逐项验证清单

  • DM #0～#5 逐轴短距离前进/后退，方向与机械定义一致。
  • 任意步进运动中发送 STOP，实际停止位置不会被当作完整目标位置。
  • 发送 ESTOP，确认收到唯一响应 OK,ESTOP，全部步进/轨道停止且两路闭环失能。
  • 硬件急停（GPIO35，默认启用）：用常闭按钮接 GPIO35↔GND；按下应上报 HWESTOP,TRIGGERED 并停止全部输出，松开后自动复位。该机制是软件急停，仍需独立的切断电机功率的硬件断电急停按钮。
  • GEAR 0 低输出闭环点动，编码器 A/B 计数方向与目标方向一致。
  • GEAR 1 重复相同步骤，不直接复制未经验证的 PID 参数。
  • 轨道 D 低占空比前进 → 停止 → 后退，GPIO40/41 对应正确。
  • 轨道 D 控制端断开或租约到期时自动停止。
  • 如使用手机网页端，确认手机断网/锁屏后轨道 D 不会持续运行。
  • 如使用 AUX，只在固件已正式实现对应 UART/I²C 后连接 Pico、扩展器或 RS485；当前仅为硬件预留。
  • AS5600 尚未安装时保持 STEPPER_ENCODER_DIAGNOSTICS_ENABLED=0；安装后先只读执行 ENC,0,S～ENC,5,S，禁止直接启用闭环。
  • AS5600 是单圈绝对传感器；掉电后多圈累计丢失，丝杠机构必须重新回零。

12. 故障排除速查

现象优先检查处理
DM 有锁力但不转（运动时 24V 电流不增）信号线接触不良、PUL-/DIR- 未共地、PUL/DIR 轴号接错、拨码或脉宽断电按 §3 逐线核对；拔插 PUL+/DIR+ 信号线排除接触不良（R 轴曾因此误判驱动器损坏）；万用表测 GPIO 端有 3.3V 翻转即 ESP32 正常，病根在 DM 侧回路
某两路 DM 同时异常是否把 6 轴旧图当成双轴图接线按 GPIO 5/6、7/15、1/2、4/8、9/10、38/39 重新核对
DRV8871 / N20 发热VM_MOTOR 电压过高、堵转、模块 pin 顺序错误立刻切断 VM，按铭牌和实物模块资料检查

AS5600 角度跳变磁铁偏心/间隙、长线干扰、相邻采样跨越半圈停止机构，改善安装与线束；重新上电回零后再验证
