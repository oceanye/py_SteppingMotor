## 2. 修复内容（08-19 提交）

### 2.1 bug：参数手输静默失效（pc_gui.py）

- 现象：在"脉冲/转/减速比/导程"输入框**键盘输入**的值完全不生效（只有点上下
  箭头才生效）。`ttk.Spinbox` 的 `command=` 只在箭头点击时触发，无 trace/回车/失焦
  绑定；发送运动命令用的是内存旧值。
- 后果：用户在界面填了正确参数但系统仍按旧参数运行，且无任何提示。
- 修复（两处）：
  1. `_build_ui()` 之后为三个参数 var 绑定 `trace_add("write")` →
     `_on_axis_param_change`，任何方式改值（手输/箭头/程序 set）立即生效。
     注意绑定必须放在 `_build_ui()` **之后**：`_load_axis_config()` 在 UI 建成前
     set var，提前绑定会触发回调访问未建成控件。
  2. `_send_mm()` 计算脉冲数前强制调用一次 `_on_axis_param_change(axis)` 兜底。
- 验证：`py_compile` 通过；08-19 全天实测手输参数（减速比 1.0→36）即时生效。

### 2.2 复审修正：线程安全、非法输入和滚轮焦点

- 已移除 `_send_mm()` 工作线程对 Tk 变量/控件的直接访问；运动参数改为只在 UI 线程
  校验并同步到普通 Python 缓存，工作线程只读缓存。该跨线程调用是“运动后调整窗口可能
  退出”的高风险候选根因，仍需在现场按原步骤复现确认。
- 脉冲/转、减速比和导程为空、非数字、非有限值或超出 Spinbox 范围时，GUI 会明确
  拒绝运动；Web 配置接口也会先校验再接纳，不再静默沿用旧缓存值。
- 日志滚轮按鼠标所在位置从顶层窗口路由，不再用 `<Enter>→focus_set()` 抢走参数输入框
  的键盘焦点。
- **直线能动、切到旋转后不动的根因已修复**：旧代码在每次模式切换时无条件把
  `position_trusted` 设为 false，而 MOVE 安全检查会拒绝所有位置不可信的轴。现在仅在
  轴完全停止时允许切换，并按 `旧单位值 × 旧脉冲/单位 ÷ 新脉冲/单位` 换算当前位置和
  软件限位，保留原可信状态及脉冲等价性；运动中切换会恢复原选项并明确提示。

### 2.3 数据：错误标定遗留（.stepper_axis.json，不入库）

- 轴 0/1 的 `gear_ratio` 存有历史拟合值 **21.0/21.5**（来源不明的实测拟合，本
  次证明与实际机械不符）。
- 后果：`200 × 21.5 / 1.0 = 4300 脉冲/mm`，1mm 命令 → 4300 脉冲 → 实际 21.5mm
  （用户报告"1mm 走了约 2cm"）。
- 现场配置修正：两轴 gear_ratio → 1.0；08-19 用户按 §3.2 将轴 0 改为 36.0（减速箱）。
  该变更只存在于被忽略的 `.stepper_axis.json`，不是仓库内自动迁移；其他机器必须人工
  核对并重配，不能仅靠拉取代码消除旧的 21.0/21.5。
- 当前有效标定快照（`.stepper_axis.json`，本文件被 .gitignore 排除，换机需重配）：

| 轴 | mode | pulse_per_rev | gear_ratio | lead_mm | 说明 |
|---|---|---:|---:|---:|---|
| 0 / L | rotary | 200 | **36.0** | 1.0 | 减速箱电机，360°=7200 脉冲=输出一整圈 |
| 1 / R | linear | 200 | 1.0 | 1.0 | 贯通丝杆，1mm=200 脉冲=丝杆一整圈（实测精确） |
| 2–5 / A–D | linear/rotary | 200 | 1.0 | 1.0 | 未接硬件；开环 DONE 不代表有电机 |

## 3. 实测结论与硬件档案更新

### 3.1 轴 R（贯通丝杆直线轴）——验证通过 ✅

- 电机 28HD140GT81-200LR（贯通式丝杆，导程 1mm/转）；DM422 拨码整步 200 脉冲/转。
- 10mm 命令（2000 脉冲）实测走 10mm，输入=实际一致。
- 两种模式底层同为脉冲输出，仅单位换算不同：`直线=mm×ppr×gr/lead`，
  `旋转=°×ppr×gr/360`。

### 3.2 轴 L（旋转轴）——接触故障已修，参数待慢速复测 ⚠️

- **用户确认：该电机自带减速箱**。由实测反推：整步 200 脉冲=电机一整圈时输出轴
  只转约 10° → 360/10=36，即 36:1（标准减速比；360°/7200 脉冲整圈测试因 §4 故障
  未完成最终确认，若实测非整圈按 `脉冲每输出整圈 = 7200×实际圈数分之一` 修正）。
- 正确 GUI 参数：脉冲/转=200（驱动器细分）、减速比=36、模式=旋转。
  360° = 200×36 = 7200 脉冲 = 输出轴一整圈。
- 36:1 减速的附加影响：输出分辨率 0.05°/脉冲、扭矩放大 36 倍；但普通速度档
  （按 mm/s 或 °/s × 7200 脉冲/圈换算）极易触顶（见 §5.1）。

### 3.3 两块 DM422 拨码

- 用户确认两块细分均拨在 200 脉冲/转（整步）。此前 08-18 曾据"4300 脉冲走 2cm"
  推测驱动器细分为 200，与轴 R 实测一致；轴 L 的"200 脉冲只转 10°"由减速箱
  解释（非细分差异），模型自洽。

## 4. 轴 L 状态：接触不良已修复，行程偏差待定 ⚠️（08-19 15:15 更新）

### 4.1 已解决：14:50 起完全不动

- 原因：**信号线接触不良**（交叉测试拔插后接头松脱）。用户重新压紧接口 +
  断电重启后恢复转动。
- 教训：该台架杜邦线/接头易松，运动异常时先重压接口、断电重启再排查。

### 4.2 未解决：360° 命令只转约 60°

- 现象：15:07:32 旋转 360°（7200 脉冲，固件 DONE 全部执行）输出轴只转约 60°；
  而上午实测 200 脉冲=10°（折合 36:1，7200 脉冲应为一整圈），两次观测差 6 倍。
  原记录同时写了“34°/s”和“18 秒”，但 360°/34°/s≈10.6 秒，三者不自洽；应以
  原始 TX 命令的 `delay_us`、开始/结束时间和逻辑分析仪结果为准，不把该速度当作实测值。
- 候选解释：①34°/s 快速启动丢步（若慢速精确则成立）；②整理接线/断电期间
  DM422 细分拨码被误动到 1200/1600（×6/×8 细分）。
- **待办（从这里继续）**：
  1. 两块 DM422 并排逐位对比 SW1~SW8 位置（以轴 R 为基准）；
  2. 慢速整圈验证：旋转模式、速度档 3.0（16.67ms/脉冲）、360°、贴胶带盯全程
     2 分钟——正好一圈→参数正确，事故=快速丢步（旋转限速 ≤3°/s，见 §5.1）；
     只转 60°→拨码 1200 档；只转 45°→拨码 1600 档；其他角度按比例反算。
- GPIO 分配（config.h，GEAR 构建）：L=5/6，R=7/15，A=1/2，B=4/8，C=9/10，
  D=38/39。

## 5. 已知问题与复审状态（GUI）

1. **速度超限静默钳位**：`_speed_to_delay_ms` 将 LOW 延时钳到 0.05ms；本地固件另有
   50us HIGH，因此名义周期至少约 100us（不计调度/yield），不是原记录所写的 20kHz。
   08-19 14:08 观察到“1mm @ 0.05ms 不动”，但现有证据不足以唯一归因为脉冲频率；
   还需核对 3.3V 光耦输入电流、加速曲线、驱动电流/细分和机械负载。UI 后续应显示
   钳位警告；任何 8k/10k 脉冲/秒上限都必须经逻辑分析仪和逐轴负载测试后确定。
2. **速度档不适配高减速比轴**：SPEED_PRESETS 最高 10（°/s），36:1 轴转一圈最短
   36 秒（未超速前提下）。若旋转轴需更快，需扩充档位/自由输入并配合 1 的限速。
3. 轴 L 用途为旋转，建议界面禁用/隐藏其直线模式，避免 mm 虚拟单位误导超速。
4. `MOVE,1,400,x,600000` 类命令曾触发 `ERR:busy`（上午连点）：GUI 已有 10 秒等待
   + 强制清标志逻辑（`_send_pulses`），仅提示用户避免运动中连发。
5. ~~**BUG：日志区滚轮无法滚动**~~ **已修复并复审**（08-19）：顶层窗口根据鼠标
   所在位置把滚轮路由到日志 Text，不抢走参数输入框焦点。
6. **BUG（已修复高风险候选，待现场复现确认）：执行运动任务后调整窗口大小导致程序整体退出**。
   复现：做过一次运动操作后，调整窗口大小（start_gui.bat 以 `python pc_gui.py`
   控制台方式启动，黑框与 Tk 主窗口并存，用户未区分所指），程序自动关闭。
   `log()` 与进度刷新均经 `_post_ui` 队列，但 08-19 新增的 `_send_mm()` 兜底曾在
   运动工作线程直接调用 `_on_axis_param_change()` 并访问 Tk；复审已移除该路径。
   若仍复现：①临时改 bat 为
   `python pc_gui.py 2>gui_crash.log` 复现抓栈；②审计串口线程→UI 的其余调用点
   （如 :1031 上下文）统一走 `_post_ui`；③用 `pythonw` 无控制台启动对照，
   区分 Tk 崩溃与控制台交互问题。
