# 局域网手机网页控制（X42S，2026-10-21）

PC 端 `pc_gui.py` 启动唯一串口会话，同时在 `0.0.0.0:8765` 启动局域网 HTTP
服务。手机和 ESP32 不直接通信；网页请求先进入 PC 控制层，再由共享串口会话向
ESP32 发送命令。

```text
手机浏览器 ── Wi-Fi/LAN ──> 台式机 pc_gui.py ── USB 串口 ──> ESP32-S3
```

## 使用方法

1. 台式机和手机连接同一个可信局域网。
2. 启动 `pc_gui.py`。GUI 顶部会分别显示网页服务状态、台式机局域网地址、固定端口
   `8765` 和“手机完整网址”，例如 `http://192.168.1.20:8765/`。
3. 在 GUI 中连接 ESP32 串口。
4. 点击“复制手机网址”，把固定网址发到手机并用浏览器打开。页面顶部显示“串口已连接”
   后即可控制；“服务在线 · 串口未连接”表示网页能访问，但还不能驱动电机。

网页入口不使用登录或安全令牌，同一台式机局域网地址和端口不变时，手机可一直收藏并
复用该网址。DHCP 可能改变台式机 IP；若需要长期完全固定，应在路由器中为台式机设置
DHCP 地址保留。

Windows 防火墙第一次询问时，只允许“专用网络”。由于控制入口没有认证，必须避免将
8765 端口转发到互联网，也不要在公共 Wi-Fi 上使用。

## 页面功能

- 四个逻辑电机状态卡：固定显示 `Mup1`、`Mr1`、`Mup2`、`Mr2` 的 X42S ID、
  驱动器实测反馈换算位置、独立指令目标、新鲜度和运行状态。Mup 为机构 mm，
  Mr 为减速后输出轴 deg；跟随误差是电机轴°，速度是电机轴 rpm，不能混用。
  旋转盘使用机构角度；升降没有有效行程范围时只显示 mm，不虚构百分比。
  缺失/过期/断连不回退到 0；保留旧值时明确标为“历史 / 未确认”并停止绘制有效指针。
  状态响应缺项或服务断开会清除缺失卡片，恢复连接后自动继续。
- **历史 STEP/DIR 维护默认关闭**：正常 X42S 状态不发布30个虚拟步进轴，
  `/api/stepper/move`、`config`、`stop` 全部返回409。只有桌面显式设置
  `STEPPER_LEGACY_STEPDIR=1` 并使用对应旧固件时，才开放以下旧功能：
  ESP32 本地轴 0..5，加6个Pico节点远端轴6..29；支持距离、速度、
  直线/旋转模式、脉冲/转（PPR）、减速比（GR）、丝杆导程、前进、后退和单轴停止。
  页面每秒刷新已应用配置、当前位置可信度、运动状态和软限位，但不会覆盖正在编辑、尚未
  点击“应用轴配置”的输入。
- 历史步进速度输入提供与桌面 GUI 相同的 24 个候选档位。请求超过 `1000 pps` 时，网页先显示
  失步风险确认；API 仍会独立校验，不能只绕过浏览器提示。若控制器最小周期导致速度
  钳位，页面会同时显示请求脉冲率和预计有效脉冲率。
- 2 路独立闭环电机：FOC/GEAR、使能、失能、归零、目标角。**不是四台X42S**。
  初次根据固件模式初始化选择；之后刷新不覆盖用户的模式草稿，后台仍校验固件模式。
- 轨道 D：PWM 百分比、按住前进、按住后退、停止。
- 全局软件急停：调用固件原子 `ESTOP`，停X42S/轨道及对应构建中的旧步进，
  处理独立闭环轴；仅收到 `confirmed=true` 才显示已确认。并非断电或硬件安全认证。

为避免把需要现场基准和硬件联锁的操作暴露到无认证页面，以下功能仍只在桌面 GUI
提供：逻辑电机绑定、设置原点、校准当前位置、修改软限位、绝对位置运动、连续步进和诊断。
X42S 点动、双侧基准和步态执行同样仅在桌面提供；这是保留的控制边界，不是网页遗漏。
网页没有逻辑绑定写接口，也没有协调运动启动接口。历史远端轴
6..29 只有在 ESP32 烧录 `*_remote` 固件且对应 Pico 节点在线时才能实际运动；页面显示
30 轴不代表普通（非 remote）固件具备远端轴。

轨道 D 使用租约控制。网页按住按钮时，上次请求完成后约350ms续租，每次租约1000ms；松开、
切到后台、浏览器断开或网络中断后，ESP32 最迟在租约到期时自动停止。网页 STOP 仍是
软件急停，不能替代断电急停按钮和硬件限位。

## HTTP API

所有 `/api/*` 请求均为同源、无令牌接口，请求和响应为 JSON。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/status` | 串口、四角色实测快照、独立GEAR/FOC及轨道；旧拓扑默认空 |
| POST | `/api/stepper/move` | 仅显式历史模式：单轴距离运动 |
| POST | `/api/stepper/stop` | 仅显式历史模式：停止旧步进轴，不适用X42S |
| POST | `/api/stepper/config` | 仅显式历史模式：应用旧轴参数 |
| POST | `/api/motor` | 独立GEAR/FOC轴，不是X42S接口 |
| POST | `/api/track` | 轨道 D 前进、后退、停止 |
| POST | `/api/estop` | 触发固件原子 `ESTOP`：停止全部步进/轨道并失能闭环轴，等待确认 |

服务只提供固定的 `web/index.html`、`styles.css` 和四个JS模块白名单；CSP禁止内联脚本。
拒绝目录遍历、未知 JSON 字段、超范围数值、超过
16 KiB 的请求体和跨域请求。接口没有身份认证，只能部署在可信局域网中。

### 历史 STEP/DIR 协议兼容说明（不是X42S的参数与门槛）

旧步进 MOVE 在返回 `accepted` 前会同步取得该轴预约和配置快照；配置修改与 MOVE 不能
交叉使用两套单位。单轴 STOP 会先取消尚未写串口的旧 MOVE，并把该轴保持为忙，直到
收到精确的 `OK,<axis>`。距离、速度和目标必须为有限数；若请求速度需要超过协议允许的
`10,000,000 us/step`，接口会在预约前拒绝并返回当前轴可达到的最小速度。

`POST /api/stepper/move` 的可选字段 `confirm_high_rate` 必须是 JSON 布尔值。请求脉冲率
超过 `1000 pps` 时必须明确传 `true`，否则返回 `409 Conflict`。成功响应除 `ok`、`accepted`、
`axis` 外还包含：

- `requested_pulse_rate_pps`：由速度和当前已应用轴参数计算的请求脉冲率；
- `effective_pulse_rate_pps`：按目标控制器周期模型和最小周期估算的有效脉冲率；
- `speed_clamped`：请求速度是否被最小周期钳位。

ESP32 本地轴沿用短周期约 `200 us` 执行开销补偿，速度换算上限约为 `4000 pps`；Pico
PIO 的 `delay_us` 本身就是完整上升沿周期，不应用 ESP32 补偿，协议最小周期为 `100 us`
（理论上限 `10000 pps`）。这两种时序模型在桌面 GUI 和 Web API 中按轴拓扑选择。

## 模块与浏览器回归

- `web/common.js`：请求超时、错误提示、数值输入；未知/空值不当0。
- `web/logical-motors.js`：四角色状态与机构坐标可视化。
- `web/legacy-steppers.js`：显式历史维护，不与X42S单位混用。
- `web/app.js`：页面启动、状态刷新、独立FOC/GEAR与轨道租约/急停。
- `web_control.py`：生产HTTP服务；静态资源只能从固定白名单返回，不开放目录。

浏览器测试连接**生产HTTP服务及真实DesktopWebController适配器 + 假硬件应用**，
只监听 `127.0.0.1:18765`，不复用8765、不打开串口、不读写现场配置。
故障/丢字段/慢网等场景在浏览器会话内注入，服务没有新增测试后门或控制接口。
