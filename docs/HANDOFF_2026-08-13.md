## 2. 硬件急停极性修正（重要 bug fix，颠覆 2026-08-06 的实现）

**2026-08-06 实现的急停逻辑是错的，本次已修正：**

| 项 | 2026-08-06（已废弃） | 2026-08-13（当前，正确） |
|---|---|---|
| 触发电平 | `HW_ESTOP_ACTIVE_LOW=1`（低触发）❌ | `HW_ESTOP_ACTIVE_HIGH=1`（**高**触发）✅ |
| 默认启用 | `HW_ESTOP_ENABLED=1` | `HW_ESTOP_ENABLED=0`（默认禁用） |
| 构建 | 只有 esp32s3_gear | 新增 `esp32s3_gear_hwestop`（仅用于已装 NC 回路） |

**为什么是高触发**：NC 常闭按钮接 GPIO35↔GND + 内部上拉。正常态 NC 闭合导通到 GND → GPIO=**低**；按下或断线后 NC 断开 → GPIO 被上拉到**高**。所以"触发"（按下/断线）= **高电平**。低触发的旧实现会把正常态（GPIO 低）误判为持续触发。

**新行为**：
- `safety_input_is_active(pin_high, active_high)` = `pin_high == active_high`（可被 native_test 覆盖）
- 急停激活时**拒绝所有运动命令**：`MOVE`、`STDIAG`、`FOC,...,EN,1`、`FOC,...,A`、`FOC,...,H`、`TRACK,D,FWD|REV`；停止/状态查询/失能仍可用
- 急停回路断开期间每次安全轮询都重申停止（不只停一次）
- 上报 `HWESTOP,TRIGGERED`；回路恢复上报 `HWESTOP,CLEARED`（恢复**不自动重启运动**）
- GUI 增加 `HWESTOP,CLEARED` 的状态和日志处理

**烧录选择**：
- 未装 GPIO35 NC 回路 → 烧 `esp32s3_gear`（默认，急停禁用）
- 装了 NC 回路 → 烧 `esp32s3_gear_hwestop`

## 3. RP2040 远程步进扩展（24 路步进，不是 GEAR）

- **6 块普通 Raspberry Pi Pico（RP2040，非 Pico W）× 4 轴 = 24 路步进**，全局轴 6–29
- 半双工 **RS485**（ESP32 GPIO42=TX/DI、GPIO47=RX/RO、GPIO48=DE），3.3V 收发器（MAX3485/SP3485）
- ESP32 做 RS485 主站：250ms 心跳、1000ms 节点超时、广播 ESTOP、严格地址轮询
- 与 GPIO42/47 诊断 I²C **编译期互斥**（`#error`）
- GUI/Web 扩展到 **30 轴**（0–5 本地 + 6–29 远程），API 拒绝 ≥30
- Pico 节点：4 个 PIO 状态机生成 PUL（最小周期 100us，高电平 50us），DIR 用 GPIO；节点 ID 编译期 1–6
- 新环境：`esp32s3_gear_remote`、`esp32s3_gear_remote_hwestop`
- 新目录：`rp2040_stepper_node/`（Pico 固件 + 协议 + native_test）

> ⚠️ **不要与 `docs/EXPANSION_PLAN_24_GEARS.md` 混淆**：那是 24 路 **GEAR 减速电机**（DRV8871+编码器闭环）的提案，尚未实现；本节是 24 路 **步进轴**（PUL/DIR 开环），已实现。两者不能互相替代。

## 5. 合并后必须现场验证（未做，分支作者明确仅离线构建）

详见 `docs/HANDOFF_2026-08-12_OFFLINE_REVIEW.md` §4 和 `docs/HANDOFF_2026-08-12_RP2040_STEPPERS.md` §5。要点：
1. **GPIO35 NC 急停**：烧 `esp32s3_gear_hwestop`，按按钮 / 拆任一回路线 → 只报一次 `HWESTOP,TRIGGERED`、全停；回路断开期间发运动命令应返回 `ERR:hardware estop active`；恢复 → `HWESTOP,CLEARED`，保持停止。
2. **RP2040 节点**：6 块 Pico 各烧 `NODE_ID=1..6`；不接驱动器先用逻辑分析仪验 4 路 PUL/DIR（周期、50us 高、精确步数、STOP/ESTOP 后停）；2 节点总线测试再扩到 6；断主站心跳 → 1000ms 内全部停止且拒新 MOVE。
3. **30 轴 UI/API**：GUI 和网页核对轴 0、5、6、29 边界，轴 30 被拒。
4. **默认 `esp32s3_gear` 行为不变**：6 路步进 + 2 GEAR + 轨道 D + 网页 + 急停框架（禁用）应与合并前一致。
