不更改 LOW/HIGH 避让公式、机构参数、方向符号和本机标定文件。

### 复现与修复

- **界面焦点异常**：Tk 的 `FocusIn.time` 可能是字符串 `"??"`，原实现与
  点击时间相减会抛 `TypeError`。改用单调时钟；Tab 导航清除鼠标焦点抑制。
- **到位后位置仍停留在上一帧**：PC 的到位查询只检查 `reached`，未更新位置
  缓存；固件轻量探测又在 `reached=1` 时跳过位置读取。两者都会使下一段
  “累计终点 − 实测位置”用到旧数据。现在到位查询同步更新 PC 缓存，固件
  轻量探测在到位时仍读实测位置，保持每次两帧，不恢复运动中的七帧全量轮询。
  例：机构已到 10°、下一累计终点 12°，应发 2°，不能因缓存还是 0°而发 12°。
- **遥测真实性**：原合并逻辑忽略固件 `online`、`age_ms`，且无效字段沿用旧值。
  现保留真实在线状态与采样年龄，按 valid 位清空未知字段，拒绝旧绑定的回复。
  固件新查询先清字段有效位；轻探测不再把旧速度/误差等标记为本轮有效。
- **误判完成**：离线/失能/保护故障不能返回 DONE；过期或缺少实测位置的
  `reached=1` 回复继续等待，最终超时失败，不能据此继续下一运动段。
  轻探测未提供速度且尚未到位时，也禁止把未知速度当作静止来记零。
- **2Hz 轮询与 200ms 门槛冲突**：四台后台轮询错开，正常在线数据也会超过
  200ms，导致启动/记零被拒。现在对已在线但过期的样本重新请求一次状态，
  再执行原门槛检查；查询失败不放行，不放宽 200ms 门槛、不提高后台轮询频率。
  **10-19 复审更正：这不是完整修复。固件 `X42S,S,id` 只返回缓存，不强制
  获取新的驱动器样本；固件缓存仍旧时依然拒绝启动。不能把“重新请求”写成
  “保证刷新实测”，也不能用收包时间把旧样本洗成新样本。**
- 手动命令无应答时补充明确的超时/取消提示，不再显示空白错误原因。

### 自动日志与诊断包

GUI 启动后默认记录，不必勾选原始串口流。每次启动生成独立会话目录：
`logs/diagnostics/<UTC时间>-<随机会话ID>/`。

| 文件 | 内容与用途 |
|---|---|
| `gui.jsonl` | GUI 操作、配置摘要、提示、启动/回调/后台线程异常及堆栈 |
| `motor.jsonl` | 串口连接、TX 尝试/写出、RX、命令排队/匹配/超时/取消、步态阶段与终态 |
| `telemetry.jsonl` | X42S 电机角度、输出端换算位置、目标、状态、故障、采样年龄；未知值为 null |
| `session.json` | 软件版本/源码摘要、环境、来源说明、队列与写盘健康统计 |

每条含 UTC、单调时间、会话内序号、线程；GUI 操作 ID 延续到控制工作线程，
每条串口请求另有 request ID。只有匹配成功的回复关联请求；异步事件另记。
`request.completed` 只表示收到匹配回复（可能还是 ERR），**不是电机完成**；
`motion.terminal` 记录执行器返回 DONE/ABORTED/TIMEOUT 等。现有线协议没有事务序号，
这些本地关联 ID **不能消除迟到同内容 ACK 的歧义**，见下方审计。

文件写入在独立线程，队列上限 8192；每通道约 2 MB/文件、保留 2 个备份，
三通道约 18 MB/会话（单条超大记录可能越过文件阈值）。保留最近 20 个已正常关闭
会话；崩溃未关闭会话、外来文件不自动删除，因此这不是磁盘总量硬上限。
队列满时不阻塞控制，累计丢弃数；写盘失败累计错误数，GUI 底部红字提示。
退出时有限等待写完；异常退出不保证最后几条已落盘。无需联网即可记录/导出。
旧 `gui_stderr.log` 保留为 pythonw 启动失败兜底；“另存原始流”仍是可选旧功能，
该旧文件与 stderr 文件不在新 JSONL 轮转策略内，需按需人工清理，不建议长期启用。

导出方式：GUI 底部 **导出脱敏诊断包**，或在项目目录执行：

```powershell
python scripts/export_diagnostics.py
python scripts/export_diagnostics.py --output docs/diagnostics/field-review.zip --label field-review
```

默认落到 `logs/exports/`，不覆盖已有同名 ZIP。导出最近 3 个会话及最多 4 个旧日志；
每文件默认截取尾部 1 MB、源日志总预算 24 MB，生成的 CSV/manifest 另计。
截断/预算遗漏明确列在 `manifest.json`；文件附 SHA256。`telemetry.csv` 可直接绘制
目标/实测/误差曲线，保留单位、减速比、导程、采样年龄与来源会话，不编造未知值。

而不是本机文件中的 190 mm 两模态配置。**GUI 冒烟的间隙数字只验证回退界面能运行，
不代表 190 mm 实机的避让已通过。** 这是版本/配置兼容问题，需另行明确配置迁移，
不能直接覆盖现场标定；本批保留原文件不改。日志中的旧 FocusIn 报错和缺 tkinter
属于历史记录，应按时间/会话区分，不应解释为本次 463 项回归仍失败。

### 实测位置替换 step 估算：可行，但不能直接等同整机绝对定位

X42S 返回的是电机轴实测角。旋转输出角 = 电机角 / 减速比；直线位移 =
电机角 / 减速比 × 导程 / 360。机构零位、安装方向、连续角展开、反馈有效位、
在线状态和采样年龄仍需要配套验核。本次遥测日志同时保留原始角及输出单位，
不能把驱动内部闭环当成“减速器后的绝对反馈”，也不能据此直接测得整体平面 XY。
数字孪生的整机位姿仍依赖标定、支撑假设及运动学；打滑、回差、柔性变形无法仅靠
电机编码器排除。当前界面尚有如下不完整的 X42S 迁移，不能统称已全部替代估算。

## 4. AS5600、TCA9548A 与 PCF8575

### 4.1 模块关系

```text
ESP32 GPIO42/47 I²C
  |-- TCA9548A @ 0x70
  |     |-- CH0 --> AS5600 #0 @ 0x36
  |     |-- CH1 --> AS5600 #1 @ 0x36
  |     |-- CH2 --> AS5600 #2 @ 0x36
  |     |-- CH3 --> AS5600 #3 @ 0x36
  |     |-- CH4 --> AS5600 #4 @ 0x36
  |     `-- CH5 --> AS5600 #5 @ 0x36
  `-- PCF8575 @ 0x20（DNP，未来低速逻辑扩展）
```

- TCA9548A 解决 6 个 AS5600 固定地址冲突；每个传感器独占一个 mux 通道。
- PCF8575 不能解决 AS5600 地址冲突，也不能生成 DM442 的实时 PUL。
- 6 路 PUL 和当前 DIR 始终保留为 ESP32 原生 GPIO。
- PCF8575 的 P0–P5、P6–P11 分别仅标注为未来 DIR、ENA 逻辑候选，P12–P15 预留。当前 PCB 不把这些端口硬连到 DM442。
- PCF8575 是准双向口且上电默认高；连接 DM442 光耦输入前，必须根据实物输入电流、共阳/共阴接法和电平增加并验证成品开集电极/ULN 类缓冲模块。
- TCA、PCF 及 AS5600 模块必须工作在 3.3 V 兼容 I²C；禁止把模块自带 5 V 上拉直接送入 ESP32 GPIO。

### 4.2 当前诊断协议

安装模块并把 `esp32_stepper/src/config.h` 中 `STEPPER_ENCODER_DIAGNOSTICS_ENABLED` 显式改为 `1` 后，可查询：

```text
ENC,<axis>,S
```

响应格式：

```text
ENC,<axis>,S,<diag>,<mux>,<online>,<magnet>,<raw>,<single_deg>,<runtime_multi_deg>,<age_ms>,<errors>
```

该路径只读取状态和角度，不调用 MOVE/STOP，也不修改 PUL/DIR。TCA 或 AS5600 缺失必须保持非致命，不能阻止默认步进功能启动。

AS5600 是单圈绝对角度传感器。`runtime_multi_deg` 是固件通电期间通过跨零展开得到的 RAM 累计值，重启/掉电后丢失；多圈丝杠位置仍必须配合原点/限位建立机器坐标。

5. 用 KiCad 8/9 打开工程，检查 courtyard/机械干涉、重新铺铜并执行 DRC。
6. 复核网络表、电源域、连接器方向和丝印，再生成 Gerber；当前 MOCK 版不得直接投板。

当前生成物统计为 212 个焊盘、61 个网络，仅用于设计交接和布局预览，不代表 DRC 或
可制造性已经通过。

### C. 无电机功率的逻辑验收

1. 只给 ESP32 USB 供电，确认无异常发热和复位循环。
2. 串口发送 `MODE`，应返回 `MODE,GEAR`。
3. 逐轴示波器/逻辑分析仪检查 PUL、DIR；先不接 DM442 功率端。
4. 检查 `ESTOP` 响应 `OK,ESTOP`，并确认所有输出停止、旧工作线程不能再次启动电机。
5. 如烧录 `esp32s3_gear_hwestop`：闭合 NC 回路后允许控制；按下急停或拆断任一根回路线应上报 `HWESTOP,TRIGGERED`，并在保持断开时拒绝 `MOVE`、`FOC,...,EN,1`、`FOC,...,A`、`FOC,...,H` 和 `TRACK,D,FWD|REV`；恢复回路后应上报 `HWESTOP,CLEARED`，不得自动恢复运动。
6. 启动 GUI 与手机网页，确认 GUI 显示的网址和端口可由手机访问、串口只有 GUI 占用、网页断开后轨道 D 租约会超时停车。

### D. 当前开环逐轴验收

1. 确认 DM442 24 V 不经过载板，DRV8871 的 `VM_MOTOR` 与电机额定电压匹配，各电源公共地。
2. 每次只接一轴、低速、小步数、机构脱离硬限位，核对方向。
3. 根据驱动器细分拨码和丝杠导程重新标定 `pc_gui.py` 的 `PULSES_PER_MM`；当前数值不能视为六轴实测结果。
4. 逐轴测试 STOP、ESTOP、串口拔出、GUI 关闭和轨道 D 租约超时。
5. 安装并验证硬件限位和切断功率的急停后，才允许扩大行程和速度。

### E. 编码器安装与只读诊断

1. 将径向磁铁与每根步进轴同轴安装，检查间隙、偏心、极性和机械固定。
2. 实测 TCA/AS5600 模块针序与 3.3 V 上拉；I²C 线尽量短，并与电机线分离。
3. 先保持 `STEPPER_ENCODER_CLOSED_LOOP_ENABLED=0`，仅把 `STEPPER_ENCODER_DIAGNOSTICS_ENABLED` 改为 `1`。
4. 查询 6 路 `ENC,<axis>,S`，验证 mux、在线、磁铁、原始角度、方向、跨零连续性和错误计数。
5. 同时运行开环小步运动，对比“命令脉冲推算位置”和编码器位置；建立每轴方向符号、传动比、零位和允许误差。

### F. 未来闭环落地

当前仓库故意用编译期保护阻止把尚未实现的闭环标志直接打开。未来实现至少要包含：

1. 原点/限位流程和掉电后的坐标恢复策略；
2. 每轴命令位置到编码器角度/丝杠位移的标定模型；
3. 失步检测门限、滤波、持续时间和故障锁存；
4. 速度受限的补偿策略，避免外环频繁追加脉冲或正负抖动；
5. 编码器掉线、磁铁异常、I²C 超时、TCA 掉线时立即退回安全停机，而不是盲目继续；
6. 与 STOP/ESTOP、软件限位、硬件限位和网页并发控制的统一状态机；
7. 单轴台架验证完成后再逐轴启用，禁止“检测到编码器即自动闭环”。
